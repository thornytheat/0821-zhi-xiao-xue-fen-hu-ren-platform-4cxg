# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

# 同一申请补录课程

1. 首个批次可直接在“补录签发”面板填写申请编号（如 `0001`）并提交；也可先在上方执行 `clean` 样例并点“签发”，系统会自动锁定其配对。
2. 补录批次填写同一申请编号与回执编号（建议填写，回执中断后用同一编号重试即可，不会重复计学分）。可选择“撞课换组样例”或上传自己的 CSV。
3. 结论为“已签发”时，面板显示本批认定学分与最终配对；若发生换组，会标注“已换组配对”。
4. 结论为“撞课待重算（RECALCULATE / COURSE_CLAIMED）”时，说明与另一批并发或已签发课程相撞；按最新锁定课程重新核算、换组达到本批最低学分后再次提交。
5. 右侧“该申请的签发结论与原因”和“已锁定抵扣课程”可随时复查；接口见 [HTTP 接口](HTTP.md)。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
